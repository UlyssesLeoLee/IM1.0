## 1. IM1.0 现有法规相关基线

### 1.1 SRS 现有合规声明（per SRS §32 合规声明）

> "本文档提出满足常见隐私诉求（删除/导出/驻留）的架构能力，但**不声称系统已完全符合 GDPR 或其他特定法域法规**——最终合规需法务评审与租户具体部署配置确认。"

**数据来源**：SRS.md v0.2 §32 合规声明
**验证日期**：2026-09-01 JST

### 1.2 SRS 现有 Privacy 要求（per SRS §32 PRIV-FR-001~004）

| ID | 要求 | 优先级 | 架构能力 |
|---|---|---|---|
| PRIV-FR-001 | Delete Account / Delete Message / Data Export | P0 | 已纳入 |
| PRIV-FR-002 | Data Retention 策略按租户/会话类型 | P1 | 已纳入（per BasicDesign §14.3） |
| PRIV-FR-003 | AI Data Usage Opt-out、Telemetry Opt-out | P1 | 已纳入 |
| PRIV-FR-004 | Region Storage（数据驻留） | P2 | V1/V2 能力，取决于部署形态 |

### 1.3 SRS 现有 Security 要求（per SRS §30 SEC-NFR-001~007）

| ID | 要求 | 优先级 |
|---|---|---|
| SEC-NFR-001 | 全链路 TLS | P0 |
| SEC-NFR-002 | RBAC + ABAC | P0 |
| SEC-NFR-003 | Token 短生命周期 + Rotation + 设备绑定 | P0 |
| SEC-NFR-004 | Rate Limit / Anti-spam / Anti-replay | P0 |
| SEC-NFR-005 | 游戏客户端视为不可信（Server-to-Server 强制） | P0（红线） |
| SEC-NFR-006 | 审计日志覆盖身份/权限/Extension/管理操作 | P0 |
| SEC-NFR-007 | 静态加密 | P1 |

**数据来源**：SRS.md v0.2 §30/§32
**验证日期**：2026-09-01 JST

### 1.4 IM1.0 业务场景可能触发的法规（推断）

- **游戏品类**：社交游戏 / MMO / 大逃杀 / 休闲 / 赌博类（部分国家禁）
- **身份**：Guest + 第三方（Steam/Xbox/PSN/Epic/自定义 OIDC）
- **数据**：用户身份 + 消息 + 媒体 + Presence + 好友关系
- **部署形态**：私有化（on-prem）+ SaaS

**Known gap**：IM1.0 目标市场清单未明（1 人公司 = Ulysses 尚未确认）

## 2. 中国大陆（CN）法规

### 2.1 主要法律清单

| 法律 | 实施日期 | 适用范围 | 关键义务 |
|---|---|---|---|
| 《网络安全法》 | 2017-06-01 | 网络运营者 | 实名认证 / 日志留存 60 天 / 等保 |
| 《数据安全法》 | 2021-09-01 | 数据处理活动 | 数据分类分级 / 数据本地化（CIIO） |
| 《个人信息保护法》（PIPL） | 2021-11-01 | 处理个人信息 | 告知同意 / 数据本地化 / 跨境传输安全评估 |
| 《关键信息基础设施安全保护条例》 | 2021-09-01 | CIIO | 强本地化 + 安全审查 |
| 《互联网用户公众账号信息服务管理规定》 | 多次修订 | 公众账号 | 实名认证 + 后台实名为 P0 |
| 《网络数据安全管理条例》 | 2025-01-01 (草案) | 大型网络平台 | 需关注立法动向 |

**数据来源**：Mavis 训练数据（基于 npc.gov.cn / cac.gov.cn 公开法规文本）
**验证日期**：2025-12（训练数据截止，截至 2026-09-01 可能已有修订需法务确认）

### 2.2 对 IM1.0 的影响（推断，非法律意见）

| 能力 | 法规要求 | IM1.0 现状 | 差距 |
|---|---|---|---|
| 实名认证 | 网络安全法 §24 | H-7 待决策 | **H-7 必须落地** |
| 消息/操作日志留存 | 网络安全法 §21 争议（60 天） | Observability 默认 30 天 | **需 ≥ 60 天**（法务确认） |
| 数据本地化 | 数据安全法 §31 (CIIO) | PRIV-FR-004 标 P2 (V1/V2) | **CIIO 客户需 P0** |
| 跨境传输安全评估 | PIPL §38-39 | 未实现 | **V1+ 需求** |
| 用户删除权 | PIPL §47 | PRIV-FR-001 P0 已纳入 | 满足 |
| 数据导出权 | PIPL §45 | PRIV-FR-001 P0 已纳入 | 满足 |
| 单独同意 | PIPL §23/29 | 未明确 | **需 UI 改造**（法务确认范围） |
| 最小必要 | PIPL §6 | 隐私设计待落地 | **需隐私设计评审** |

### 2.3 CN 法规强制前置项（IM1.0 中国上线前必做）

1. **实名认证供应商**（H-7）：与短信网关组合（阿里云/腾讯云/华为云）
2. **日志留存 ≥ 60 天**（修改 Observability 保留期）
3. **个人信息处理告知同意 UI**（IM 客户端 + Web Dashboard 隐私弹窗）
4. **数据本地化部署**（CN 区域 K3s 独立部署）
5. **等保 2.0 三级以上**（IM 平台按"重要信息系统"评级）

**Known gap**：等保评级具体级别需法务 + 客户业务确认

## 3. 日本（JP）法规

### 3.1 主要法律清单

| 法律 | 实施/修订 | 适用范围 | 关键义务 |
|---|---|---|---|
| 《個人情報保護法》(APPI) | 2003 实施 / 2017, 2022 修订 | 个人信息取扱事業者 | 告知 / 同意 / 数据主体权利 |
| 改正 APPI 2022 | 2022-04-01 全面施行 | 所有取扱事業者 | 跨境传输同意 / 漏えい報告 / 仮名加工情報 |
| 《特定商取引法》 | 修订 | B2C 订阅 | 取消条款明示 |
| 《青少年インターネット環境整備法》 | 2009/修订 | 未成年人 | 过滤 / 家长控制 |

**数据来源**：Mavis 训练数据（基于 japaneselawtranslation.go.jp / ppc.go.jp 官方法规文本）
**验证日期**：2025-12（训练数据截止）

### 3.2 改正 APPI 2022 关键变化

- **跨境传输**（§28）：向境外提供个人信息需满足以下之一：
  1. 取得本人明示同意
  2. 接收方所在国与日本有"同等保护水平"认定
  3. 接收方符合 APPI 标准（合同/认证）
- **漏えい報告**（§26）：发生个人信息泄露时需向 PPC 报告
- **仮名加工情報**（§2-9）：加工后信息有独立定义

### 3.3 对 IM1.0 的影响

| 能力 | 法规要求 | IM1.0 现状 | 差距 |
|---|---|---|---|
| 利用目的明示 | APPI §17/21 | PRIV-FR-003 Telemetry Opt-out P1 | 需明示 UI |
| 本人同意 | APPI §17 | 未明确 | **需 UI 改造** |
| 跨境传输同意 | APPI §28 | 未实现 | **V1+ 需求** |
| 数据主体权利（删除/导出/停止利用） | APPI §30 | PRIV-FR-001 P0 已纳入 | 满足 |
| 漏えい報告 | APPI §26 | 未实现 | **需 SRE 流程** |
| 青少年保护 | 环境整備法 | 18+ 确认无 | **视客户业务定** |

### 3.4 JP 法规强制前置项

1. **隐私政策 + 利用目的明示 UI**
2. **跨境传输同意机制**（如 IM1.0 全球部署 → JP 用户数据出境需同意）
3. **漏えい報告流程**（需 SRE 团队响应机制）
4. **PPC 报告联系人**（需法务）

**Known gap**：IM1.0 是否有 JP 客户 = 未知

| 能力 | 法规要求 | IM1.0 现状 | 差距 |
|---|---|---|---|
| 知情权 | CCPA §1798.100 | PRIV-FR-001/003 P0/P1 | 满足 |
| 删除权 | CCPA §1798.105 | PRIV-FR-001 P0 | 满足 |

### 4.4 US/CA 法规强制前置项

**Known gap**：US 各州法律差异大，IM1.0 需法务按目标州逐项确认

## 6. IM1.0 法规适配建议（不替 Ulysses 决策）

### 6.1 MVP 阶段（12 周）建议

| 建议 | 优先级 | 理由 |
|---|---|---|
| 维持 MVP 不直接对最终消费者 | P0 | 1 人公司无法承担全球合规成本；客户（B 端游戏开发商）承担终端用户合规 |
| PRIV-FR-001（删除/导出）P0 必保 | P0 | 三地通用能力，架构成本低 |
| PRIV-FR-002（Retention 可配）P1 必保 | P0 | 与 BasicDesign §14.3 一致 |
| H-7 实名认证供应商决策 | P0 | CN 客户必填 |
| 法务预算（外部律所） | P0 | 1 人公司无法解读多地法规 |

### 6.2 V1 阶段建议

| 建议 | 优先级 |
|---|---|
| PRIV-FR-004 Region Storage 落地 | P1 |
| 等保 2.0 合规（如目标 CN 客户） | P1 |
| 跨境传输同意 UI（APPI §28） | P1 |
| CCPA Opt-out 链接 | P1 |
| SRE 漏えい報告流程（APPI §26） | P1 |

### 6.3 跨客户隔离建议

IM1.0 已有 TEN-FR-001~005 多租户要求（per SRS §29），**法规隔离天然按租户/区域分**：
- 租户 A 中国部署 → CN 法规
- 租户 B 日本部署 → APPI
- 租户 C 美国部署 → CCPA
- 单租户多区域 → V1+ 评估

### 6.4 不建议

- **不建议**自行解读法规（per SRS §32 合规声明）
- **不建议**MVP 即对最终消费者（2-3 步内）开放
- **不建议**把法规适配塞进 MVP 范围（per 132-wbs.md §5.8 H-5 备注"30K-60K token 预算"远不够合规实施）

## 7. 已知缺口

### 7.1 法规时效性
1. **法规可能过期**：本文档数字基于 2025 年底训练数据，**截至 2026-09-01 可能已变更**（如《网络数据安全管理条例》2025-01 草案正式发布等）
2. **Mavis 无 web 验证能力**（per task contract）：H-5 决策时需 Ulysses 决定是否外部法务验证

### 7.2 IM1.0 业务缺口
3. **目标市场清单未明**：CN/JP/US/CA 中哪些是 IM1.0 真实市场未知
4. **客户业务品类未明**：赌博 / 社交 / MMO / 通用 触发不同法规
5. **是否涉及 < 13/18 岁用户**未知（COPPA / APPI 青少年条款）
6. **是否跨境传输数据**未知（决定 APPI §28 / PIPL §38 触发条件）
7. **法务预算与对接律所**未明

### 7.3 测量能力缺口
8. **无内部合规官**：1 人公司 = 无 DPO / 无 Security Officer
9. **等保 2.0 评级能力**：需外部测评机构
10. **SRE 漏えい報告流程**：per APPI §26 需 < 一定期限内报告，1 人公司响应能力弱

### 7.4 法规交叉缺口
11. **GDPR 缺失**：未列出欧盟 GDPR 法规（Ulysses 未在 H-5 范围点名 EU，但 IM1.0 全球化目标可能涉及）
12. **东南亚 / 韩国 / 印度**：同样未列，**业务扩展到该区域时需补调研**
13. **中国特定行业**（金融 / 医疗 / 教育）有额外法规，IM1.0 若涉入需补
